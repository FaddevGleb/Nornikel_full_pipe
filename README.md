# Hypothesis Generation for Materials Discovery and Design Using Goal-Driven and Constraint-Guided LLM Agents (We are still updating the repository)
![figure_1_matsci_increased_font drawio (1) drawio (1)](https://github.com/user-attachments/assets/d2c2c1c7-a5e4-4c79-8696-822a2d5c31e5)

Overview of our iterative hypothesis generation and evaluation pipeline (ACCELMAT). Starting from an input 
prompt and a knowledge graph, the Hypotheses Generator (GPT-4o) proposes 20 hypotheses, which are then
reviewed by three critics–GPT-4o, Claude-3.5-Sonnet, and Gemini-1.5-Flash. Their feedback is consolidated
by the Summarizer (GPT-4o); if unanimous agreement is not reached, the hypotheses along with critic feedback
are fed back to the Hypotheses Generator for refinement and are re-evaluated by the critics. Once approved,
the final hypotheses proceed to the Evaluation Agent (OpenAI-o1-preview) for scoring

Description of ACCELMAT Framework:

1). Hypotheses Generation Agent (HGA): Given the Goal Statement and Constraints, the HGA generates multiple hypotheses, accompanied by reasoning for each. This agent is
powered by GPT-4o.

2). Critic Agents (CA): The second component consists of three Critic Agents–GPT-4o, Claude-3.5-Sonnet Anthropic, and Gemini-1.5-Flash. These
agents are provided with the hypotheses generated by the HGA, goal statement, and constraints. Their role is to evaluate each hypothesis, assessing its alignment with the goal and
constraints. Each critic gives detailed feedback to guide subsequent hypothesis refinement cycles.

3). Summarizer Agent (SA): The Summarizer Agent consolidates and organizes the feedback from all three CAs into a structured format. It then provides this comprehensive feed-
back to the HGA to guide the refinement process. We use GPT-4o as the SA.

4). Evaluation Agent (EA): The Evaluation Agent is used to evaluate the closeness and quality of the generated hypotheses. We use OpenAI-o1-preview as our evaluation agent.

## Setup (Yandex AI Studio)

LLM calls use [Yandex AI Studio](https://yandex.cloud/en/docs/ai-studio/) via an OpenAI-compatible API.

1. Create a Yandex Cloud folder and enable AI Studio.
2. Create an API key in the [Yandex Cloud console](https://console.yandex.cloud/).
3. Copy `.env.example` to `.env` and set `YANDEX_API_KEY` and `YANDEX_FOLDER_ID`.
4. Install dependencies: `pip install -r requirements.txt`
5. Optionally change model names in `.env` (see [model catalog](https://yandex.cloud/en/docs/ai-studio/concepts/generation/models)).

Default models (tuned for ACCELMAT roles):

| Role | Env var | Model | Why |
|------|---------|-------|-----|
| Hypotheses Generator | `YANDEX_MODEL_HGA` | `yandexgpt/rc` (5.1 Pro) | Best generation quality for complex scientific tasks |
| Critic 1 | `YANDEX_MODEL_CRITIC` | `qwen3-235b-a22b-fp8/latest` | Strong instruction following, large context for 20 hypotheses |
| Critic 2 | `YANDEX_MODEL_CRITIC_2` | `gpt-oss-120b/latest` | Heavy reasoning, different model family |
| Critic 3 | `YANDEX_MODEL_CRITIC_3` | `aliceai-llm/latest` | Third independent perspective |
| Summarizer | `YANDEX_MODEL_SUMMARIZER` | `yandexgpt/rc` (5.1 Pro) | Synthesizes critic feedback into structured output |
| Evaluation Agent | `YANDEX_MODEL_EVALUATION` | `yandexgpt/latest` (5 Pro) | Reliable scoring of final hypotheses |
| Knowledge Graph | `YANDEX_MODEL_KG` | `aliceai-llm-flash/latest` | Fast agent workflow for many extraction calls |

## Knowledge Graph conversion

Convert a LearningChunkGraph JSON (e.g. from `Examples_prev_step/`) into MatKG-style triplets for [MatDes_KG.ipynb](MatDes_KG.ipynb):

```bash
python graph_to_subrelobj.py Examples_prev_step/LearningChunkGraph_dedup.json -o SUBRELOBJ.csv
```

Output CSV columns: `Subject`, `Rel`, `Object`, `Count`. Relation codes follow MatKG (`CHM`, `PRO`, `APL`, `SYN`, `CMT`). `APL-PRO` triplets are derived when a material links to both an application and a property.

Place `SUBRELOBJ.csv` in the project root before running `MatDes_KG.ipynb`.

### Extended Nornikel ontology

The pipeline also supports the extended `LearningChunkGraphNORNIKEL` schema ([`Examples_prev_step/LearningChunkGraphNORNIKEL.schema (2).json`](<Examples_prev_step/LearningChunkGraphNORNIKEL.schema (2).json>)), which adds industrial/economic node types beyond the original 5-type MatKG universe:

| Node type | Code | Node type | Code |
|-----------|------|-----------|------|
| Material | `CHM` | Source | `SRC` |
| Property | `PRO` | Equipment | `EQP` |
| Application | `APL` | BusinessMetric | `BIZ` |
| SynthesisMethod | `SYN` | InternalExperiment | `EXP` |
| CharacterizationMethod | `CMT` | Constraint | `CST` |
| FailureMode | `FLR` | HypothesisRecord | `HYP` |
| Mechanism | `MEC` | Condition | `CND` |

Edges also carry richer `attributes` (`confidence_score`, `evidence_quote`, `source_doi`, `relation_role`, `magnitude`, `direction`) which are used for the material-centric KG context below.

For graphs with **no `Application` nodes** (e.g. `Examples_prev_step/LearningChunkGraphNORNIKEL_EXAMPLE (2).json`, which models cost/equipment/regulatory constraints around a Ni-W alloy), `kg_context.py` automatically falls back to a **material-centric** context: it extracts material names mentioned in the goal, then pulls all first-degree relations of those materials directly from the graph (properties/effects, process considerations, economic and regulatory constraints) and summarizes them for the HGA prompt.

Example run against this graph:

```bash
python run_pipeline.py --request "inputs/pipeline_request_nornikel_niw.json" --output "output/hypotheses_nornikel_niw.json"
```

## End-to-end pipeline

Run the full ACCELMAT flow: **LearningChunkGraph JSON + goal + constraints → hypotheses**.

```bash
python run_pipeline.py --request inputs/pipeline_request.example.json --output output/hypotheses.json
```

Optional: save intermediate triplets:

```bash
python run_pipeline.py --request inputs/pipeline_request.example.json --output output/hypotheses.json --save-subrelobj output/SUBRELOBJ.csv
```

### Pipeline stages

1. **Graph prep** — `LearningChunkGraph_*.json` (original or extended Nornikel ontology) → SUBRELOBJ triplets ([`graph_to_subrelobj.py`](graph_to_subrelobj.py))
2. **KG context** — extract applications (or, as a fallback, materials) from the goal, query the graph, LLM summarize ([`kg_context.py`](kg_context.py))
3. **ACCELMAT** — HGA (20 hypotheses) → 3 critics (different Yandex models) → Summarizer → refinement loop → Evaluation Agent ([`agent_framework_materials_discovery.py`](agent_framework_materials_discovery.py))

### Request format (`inputs/pipeline_request.example.json`)

```json
{
  "graph_path": "Examples_prev_step/LearningChunkGraph_dedup.json",
  "goal": "...",
  "constraints": ["..."],
  "max_refinement_iterations": 5,
  "num_hypotheses": 20
}
```

### Output format (`output/hypotheses.json`)

Contains `goal`, `constraints`, `kg_context`, `hypotheses`, `evaluation`, and `metadata` (triplet count, refinement iterations, critics approval).

**Note:** Full ACCELMAT uses many LLM calls (KG + experts + 20 hypotheses + 3 critics per iteration). Set `max_refinement_iterations` lower during development to reduce cost.
